### [OpenAI 发布 GPT-6 Sol 与 Luna](https://openai.com/index/introducing-gpt-6-sol-and-luna/) ⭐️ 9.0/10

OpenAI 发布了新一代旗舰模型 GPT-6，分为 Sol 与 Luna 两个版本，消息源自其官方介绍页面。此次发布在技术社区中引发关于定价、性能表现以及工具生态（尤其是编程代理）的广泛讨论。有社区用户指出，Luna 版本的定价据称仅为 GPT-5.6 Luna 的一半，这一价格变化被看作影响用户成本结构的重要因素；Sol 版本则被视为工程与智能体工作流中的重点。由于此次提供的原始正文未包含具体技术参数、发布日期或基准测试数据，本摘要仅陈述发布事实及社区关注要点，具体规格有待官方文档确认。

hackernews · OfficialTurkey · 9月22日 18:00 · [社区讨论](https://news.ycombinator.com/item?id=49805509)

**「背景」** GPT-6 是 OpenAI 在 GPT-5.6 系列之后推出的旗舰模型代次，于 2026 年 9 月 22 日发布，并拆分为 Sol 与 Luna 两个版本，分别侧重更强的能力与更低的成本，以期将前沿智能带入日常工作中。其中 Sol 按每百万输入/输出 token 2 美元/10 美元计价，Luna 则仅为 0.10 美元/0.50 美元，整个系列的 API 价格相比 GPT-5.6 降低约一半。这一做法延续了 OpenAI 以模型代次命名，并在同一代内通过不同能力与价格定位覆盖多种使用场景的策略。

**「影响」** 对依赖 OpenAI API 或付费订阅的开发者与编程代理用户而言，Luna 版本据称约为前代一半的定价若属实，将直接降低推理成本，影响团队预算与工具选型。

**「社区讨论」** 社区评论中，有用户强调 Luna 定价仅为前代一半是重大变化，并对比了 GPT-6 Sol、GPT-6 Astra 的生成效果；也有开发者表示 5.6 Sol 在与智能体的协作“手感”上更自然，担心技术上更优的新模型未必带来同样舒适的工作体验。还有人比较了 Claude Code 与 Codex Pro 的使用限制与定价差异，整体讨论聚焦于价格、性能与工具选型，态度既有乐观，也有对更换成本与适应风险的顾虑。

### [WordPress 未认证路径遍历漏洞可致条件性 RCE，官方已全版本修复](https://github.com/WordPress/wordpress-develop/security/advisories/GHSA-7hp8-65ch-5whp) ⭐️ 9.0/10

WordPress 官方披露了一个严重的高危未认证路径遍历漏洞（GitHub 公告 GHSA-7hp8-65ch-5whp），该漏洞在特定条件下可实现远程代码执行（RCE），影响范围覆盖全部受支持的版本分支。修复版本 7.1.2 已发布，并以向后兼容方式移植回 4.7 及更早的所有受支持分支，官方建议管理员尽快升级。该漏洞涉及 locate\_template\(\) 等函数未有效阻止目录遍历攻击，若传入用户可控的模板名称，可能被利用来读取或写入系统文件。由于 WordPress 是全球最广泛使用的 CMS 平台之一，且攻击无需任何身份认证，此问题被列为紧急安全事件。

hackernews · vntok · 9月22日 16:33 · [社区讨论](https://news.ycombinator.com/item?id=49803959)

**「背景」** WordPress 在页面模板解析中存在未认证的路径穿越漏洞（CVE-2026-87902 / GHSA-7hp8-65ch-5whp），攻击者可借此绕过主题目录限制、加载主题文件夹之外的 PHP 文件，并在特定服务器配置下导致远程代码执行，严重等级为 9.2（critical），由 Robert Ressl 发现并负责任地披露。官方已在 7.1.2 版本中修复，并将其回溯至 4.7 及以上的所有受支持分支。此缺陷与 WordPress 的 locate\_template\(\) 函数有关——该函数本身不阻止目录穿越，若将用户提供的模板名直接传入便存在风险；由于 WordPress 是全球使用最广泛的 CMS 之一，此类核心级漏洞影响面极广。

**「影响」** 此漏洞影响 WordPress 4.7 至 7.1.0 的全部安装，在服务器启用 register\_argc\_argv（如官方 PHP Docker 镜像或 PHP 低于 8.5 的默认 cPanel 配置）时，未认证攻击者可通过路径遍历利用 PEAR 机制实现远程代码执行，完全控制站点服务器；官方已发布 7.1.2 修复并回溯至 4.7，但存在漏洞的站点须立即更新。

**「社区讨论」** 多数评论认可修复的及时性，但也表达了长期不满：有用户指出仅约三分之一的安装运行在最新的 7.x 分支，大量旧版站点仍面临风险；有人讽刺 WordPress 是历史上最常被利用的 Web 软件之一，并将此归咎于其庞大的攻击面。亦有开发者在评论中分享了具体补丁对比链接，还有人提到官方文档中多年前对 locate\_template\(\) 目录遍历风险警告的“讽刺性”预见。少数用户表示已通过迁移到 Hugo 静态站点彻底摆脱 WordPress 的安全负担。

### [vLLM v0.30.0 发布：模型、Fast Start 与性能优化](https://github.com/vllm-project/vllm/releases/tag/v0.30.0) ⭐️ 8.0/10

vLLM v0.30.0 发布，包含来自 315 位贡献者的 762 次提交，新增对 DeepSeek-V4.1-Flash、GLM-5.3-Flash 等多个模型的支持。新引入的 Fast Start 特性通过持久化 GPU 权重缓存守护进程和 CUDA IPC，使引擎重启时无需从磁盘重新加载权重，显著缩短启动时间；同时该特性现已覆盖 FP4 检查点与多节点张量并行。性能方面，Kimi K3 与 Qwen3.8-Flash-Next 获得多项内核优化，包括 FP8 缓存、融合内核等。量化支持扩展至 AutoRound 2-7 位、NVFP4 等。此外，多项接口变更被列为破坏性改动，如 scale-out 端点需显式开启。

github · khluu · 9月22日 05:20

**「背景」** vLLM 是开源的、面向大语言模型的高性能推理引擎，通过高效调度、KV 缓存处理、批处理与解码机制为生产环境提供模型服务。v0.30.0 的核心新特性 Fast Start 的思路是：用常驻 GPU 的权重缓存守护进程保存后量化、按张量并行切分的权重，使引擎重启时可通过 CUDA IPC 直接映射这些权重，而无需再从磁盘重新加载，从而大幅缩短重启耗时；该能力还扩展支持了 FP4 校验点与多节点张量并行。

**「影响」** 该版本为使用 vLLM 部署大型 LLM 推理服务的团队带来可测量的启动时间与吞吐提升，尤其受益于 Fast Start、模型内核优化与新增量化路径；同时，破坏性变更要求用户调整配置，例如显式启用 scale-out 端点以继续使用相关功能。
